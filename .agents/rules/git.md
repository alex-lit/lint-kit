# Работа с git

Поддержка git-проектов в рамках monorepo

## Запрет на коммиты без явного запроса

**Никогда не выполняй `git commit` (и создание тегов через `git tag`) без явного
запроса от пользователя.**

- Пользователь не просит «закоммить» - коммита не делает. Даже если кажется, что
  работа завершена и всё готово.
- Это касается любых обёрток, скриптов и инструментов, выполняющих коммит
  автоматически (например, `scripts/semver.sh`, `npm version`, `git add .`
  внутри скриптов). Перед запуском такого скрипта предупреди, что он сделает
  коммит (и что подмешает незакоммиченные изменения через `git add .`), и
  дождись подтверждения.
- `git add`, правки файлов и прочие необратимые-но-локальные действия без
  коммита - можно. Граница - именно коммит и тег.
- Если сомневаешься - спроси. Один вопрос лучше чужого коммита в истории.

Причина: коммиты - ответственность и решение владельца репозитория. История не
переписывается без боли, а незапрошенный коммит (пусть даже «правильный») лишает
пользователя выбора и подмешивает посторонние изменения.
